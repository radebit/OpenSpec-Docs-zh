初始化与更新

openspec init 在项目中初始化 OpenSpec
语法
openspec init [path] [options]
选项描述
--tools <list>非交互式配置 AI 工具。使用 all、none 或逗号分隔的列表
--language <language>设置新规划产物的语言，例如 简体中文
--force自动清理旧文件，无需提示；非交互式初始化也会自动清理旧产物
--profile <profile>覆盖此次初始化的全局 profile（core 或 custom）
--no-animation显示静态欢迎界面
--copilot-cloud选中 github-copilot 时，明确启用 GitHub 托管 coding agent 文件
--no-copilot-cloud关闭并保存云端集成设置，删除已有托管云端文件；不禁用编辑器中的 Copilot
示例
# 交互式初始化，设置规划语言
openspec init --language '简体中文'

# 非交互式：配置 Claude 和 Cursor
openspec init --tools claude,cursor --language '简体中文' --no-animation

# 配置所有支持的工具，跳过 Copilot 云端文件
openspec init --tools all --no-copilot-cloud

# 覆盖 profile
openspec init --profile core

Copilot 云端 opt-in：首次交互默认不启用；无交互且无既有选择时跳过。已有配置或托管文件会延续选择。启用后生成 .github/workflows/copilot-setup-steps.yml 和 .github/agents/openspec.agent.md。

openspec update 升级 CLI 后更新 OpenSpec 指令文件
示例
# 先升级 CLI（npm 安装方式）
npm install -g @fission-ai/openspec@latest

# 在项目内审查更新计划，再写入
openspec update --dry-run
openspec update

# 供脚本读取计划
openspec update --dry-run --json

语法：openspec update [path] [--force] [--dry-run] [--json]。--force 强制刷新，即使工具已是当前版本。

--dry-run：不写项目文件、不检查网络升级。计划列出 changes、notes、failures，执行前先检查失败项。

--json：仅可与 --dry-run 同用，单独使用会报错。

手改内容：update 会重写工具生成的技能和命令文件，也可能清理旧文件。不要依赖手改保留，先审查计划并备份。
openspec version / install 检查版本或安装独立二进制
语法
openspec version [--check] [--json]
openspec install [version]
  • version：显示版本和安装来源；--check 检查新版本，--json 输出结构化报告。
  • install：安装免 Node.js 的独立二进制，默认最新完整发布版；传入 v1.15.0 可锁定版本。
  • PATH：切换安装方式不会自动卸载旧副本。按输出提示手动处理旧安装，再打开新终端运行 openspec version 确认实际来源。

安装方式和默认路径见安装指南。这些安装命令会写入项目外目录，先取得用户同意。

Store 命令

Store 是独立的 OpenSpec 规划仓库。本机登记只负责将 Store ID 解析为本地路径。

选择规划根：对变更操作使用普通命令加 --store <id>，不要写成 openspec store new。路径须先登记，不支持 --store-path。详见核心概念。

openspec store setup 创建并登记本地 Store
语法
openspec store setup [id] [--path <path>] [--init-git | --no-init-git] [--remote <url>] [--json]
参数描述
id、--path <path>kebab-case 名称和目录。交互式会询问；无交互或 --json 时两者必填
--init-git默认初始化 Git 并创建初始提交
--no-init-git跳过所有 Git 操作，不初始化、不提交
--remote <url>在 .openspec-store/store.yaml 记录克隆来源，不自动克隆或推送；已有身份文件时不能用此选项改写
--json非交互式 JSON 输出
Git 提交：默认 setup 会创建初始提交。未获授权提交时，明确使用 --no-init-git。
终端示例：不执行 Git 操作
openspec store setup team-context --path ~/openspec/team-context --no-init-git --json
openspec store register 登记已有的健康 OpenSpec 根目录
语法
openspec store register [path] [--id <id>] [--yes] [--json]
  • path：必须显式提供；虽然帮助语法显示可选，省略仍报错。目录须已存在且 OpenSpec 结构完整。
  • --id：默认读取 Store 元数据，否则使用目录名；不能覆盖已有身份 ID。
  • --yes：同意为缺少身份的根创建 .openspec-store/store.yaml。无交互或 JSON 模式下此转换必须明确确认。
  • --json：输出登记结果。register 不克隆、不创建 Git 提交。
终端示例
openspec store register /repos/team-context --json
openspec store unregister 忘记本机登记，保留文件
语法
openspec store unregister <id> [--json]

不删除文件：只移除本机登记，Store 目录及其中的规范、变更、Git 历史均留在磁盘。

openspec store remove 移除登记并删除本地目录
语法
openspec store remove <id> [--yes] [--json]
删除警告：remove 会删除整个本地 Store 目录，包含未提交文件和本地历史。先备份。只想取消登记请用 unregister。

--yes 确认删除；无交互或 --json 时必须提供。--json 输出删除结果，不免除确认。

openspec store list / ls 列出本机登记
语法
openspec store list [--json]
openspec store ls [--json]

--json 输出 Store ID、根路径和诊断状态，不列出未登记目录。

openspec store doctor 检查登记、元数据和 Git 状态
语法
openspec store doctor [id] [--json]

省略 id 检查全部本机登记。--json 输出结构化报告；只检查，不修复。

doctor / context

openspec doctor 检查所选根目录及其关联 Store
语法
openspec doctor [--store <id>] [--json]

报告规划根、引用、缺失路径和修复建议。只读，不克隆、同步或自动修复；与检查本机登记的 store doctor 不同。

openspec context 输出所选根的工作上下文
语法
openspec context [--store <id>] [--json] [--code-workspace <path>] [--force]
  • --store：选择已登记的根；省略时按项目声明和默认 Store 解析。
  • --json：输出供代理读取的根和引用上下文，不授予跨仓库修改权限。
  • --code-workspace：显式写入 VS Code 多根文件。这是 context 唯一的文件写入。
  • --force：允许覆盖该文件；默认拒绝覆盖，父目录须已存在。
终端示例：默认只读
openspec doctor --store team-context --json
openspec context --store team-context --json

Workset 命令

Workset 是个人本机视图，不是规划根或仓库成员声明。它不授予跨仓库修改权限，也不会通过 Git 同步。

openspec workset create 组合并保存自选目录
语法
openspec workset create [name] [--member <path|name=path> ...] [--tool <id>] [--json]
  • name：无交互或 JSON 模式下必填。
  • --member：可重复。目录须存在，第一个是主目录；无交互时至少提供一个。
  • --tool：保存首选打开工具。当前默认支持 code（VS Code）、cursor；Claude/Codex CLI 打开器暂时禁用。
  • --json：非交互式创建，输出保存结果。
终端示例
openspec workset create platform --member /repos/api \
  --member web=/repos/web --tool code --json
openspec workset list / ls 查看保存的视图和成员目录
语法
openspec workset list [--json]
openspec workset ls [--json]
openspec workset open 用工具打开保存的视图
语法
openspec workset open <name> [--tool <id>]

--tool 只覆盖本次打开；无交互且未保存工具时必须提供。open 会重建本机 .code-workspace 文件，不支持 --json。

openspec workset remove 删除保存的视图，不删除成员目录
语法
openspec workset remove <name> [--yes] [--json]

仅移除视图及其生成的多根文件。无交互或 JSON 模式必须用 --yes 确认。成员目录从不改动。

浏览命令

openspec list 列出项目中的变更或规范
示例
# 列出所有活跃变更
openspec list

# 列出所有规范
openspec list --specs

# 仅归档变更 / 活跃与归档变更
openspec list --archived
openspec list --all

# 选择 Store，按名称排序并输出 JSON
openspec list --store team-context --sort name --json

选项：--changes 显式选择变更（默认）；--sort recent|name 默认 recent。--archived、--all 仅适用于变更，不能与 --specs 同用。

没有规划根：list 会报错并以非零退出，不会将未初始化目录当作空项目。先运行 openspec init，或登记 Store 后传 --store <id>。
openspec show 显示变更或规范的详情
示例
# 显示特定变更
openspec show add-dark-mode

# JSON 输出用于解析
openspec show add-dark-mode --json

# 查看 Delta 的逐需求差异
openspec show add-dark-mode --diff
  • --type change|spec：同名时明确类型；--store <id> 选择规划根。
  • --no-interactive：禁用选择提示，脚本应直接传入名称。
  • --diff：仅变更，显示 Delta 需求差异；--deltas-only 仅用于变更 JSON。
  • --requirements、--no-scenarios、--requirement <id>：仅规范 JSON，筛选需求或排除场景；ID 从 1 起。
openspec view 查看规范和变更仪表盘
语法
openspec view [--store <id>]

验证命令

openspec validate 验证变更和规范的结构问题
示例
# 验证特定变更
openspec validate add-dark-mode

# 验证所有变更
openspec validate --changes

# 验证所有内容并输出 JSON（用于 CI）
openspec validate --all --json

# 严格模式
openspec validate --all --strict --concurrency 12

# 检查归档变更是否仍有未勾选任务
openspec validate --archived

# 仅输出有问题的项目，并保留总计
openspec validate --all --report findings --json
选项描述
--all / --changes / --specs选择活跃变更和主规范的批量范围；all 不包含归档
--archived独立检查归档任务是否全部打勾及任务文件是否可读，不重新验证已合并的 Delta
--report full|findings仅限显式批量范围，不可带名称或混合归档与活跃范围；默认 full，findings 只列有问题的项目并保留完整汇总
--strict规范和活跃变更的 ERROR 或 WARNING 均导致失败；默认仅 ERROR 失败，INFO 不阻断
--type change|spec明确同名项目的类型
--json、--no-interactive结构化结果或禁用提示；无名称时脚本须指定批量范围
--concurrency <n>活跃变更和规范批量验证的并发数，默认环境变量值或 6
--store <id>验证已登记 Store 的内容

失败退出：验证失败返回非零。--all、--changes、--specs 没有可解析的规划根时会报错。运行 --archived 前先确认项目目录或显式指定 --store，避免在错误目录得到空结果。

验证范围：validate 检查规范结构和相关一致性，不运行代码测试；任务打勾也不代表实现已验证。

生命周期命令

openspec archive 归档已完成的变更并将 Delta 规范合并到主规范
示例
# 归档特定变更
openspec archive add-dark-mode

# 无提示归档（CI/脚本）：先确认实现和测试结果
openspec archive add-dark-mode --yes

# JSON 模式同样显式提供名称和确认
openspec archive add-dark-mode --yes --json

# 本次跳过主规范更新
openspec archive update-ci-config --skip-specs
  • 无交互：显式提供变更名称和 --yes。--json 不会替你确认。
  • --yes：跳过确认，可能允许带未完成任务归档；不跳过规范验证。
  • --skip-specs：本次不合并主规范；不等于变更元数据 skip_specs。
  • --no-validate：跳过验证，需要确认，不建议使用。--store <id> 选择规划根。

归档顺序：默认先校验并合并 Delta，再移动到 openspec/changes/archive/YYYY-MM-DD-<name>/。验证或规范合并失败时以非零退出，不归档。

sync：可提前将 Delta 同步到主规范，不是每次归档的必需步骤；同步失败应先修复，不继续归档。

变更元数据：在 .openspec.yaml 中声明，详见核心概念。

  • skip_specs: true：声明没有规范变更，不能同时包含 specs 文件。
  • retire_capabilities: true：明确允许在移除最后需求时退役能力、删除主规范。
  • x-*：顶层外部工具扩展字段，需小写前缀及无空白的非空名称。OpenSpec 忽略且不报未知键；其他未知键会警告，在 validate strict 模式下失败。

工作流命令

openspec status 显示变更的产物完成状态
示例
openspec status --change add-dark-mode
openspec status --all --json
openspec status --all --store team-context --json

选项：--change <id> 或 --all（全部活跃变更），--schema <name> 覆盖工作流，--json 输出状态，--store <id> 选择规划根。

isPlanningComplete：只表示规划产物齐全；兼容别名 isComplete 也是这个含义，不表示任务完成、测试通过或可以直接归档。

openspec instructions 获取产物、实现或归档指令
终端示例
openspec instructions proposal --change add-dark-mode --json
openspec instructions apply --change add-dark-mode --json
openspec instructions archive --change add-dark-mode --json

语法：openspec instructions [artifact] [--change <id>] [--schema <name>] [--store <id>] [--json]。apply 和 archive 是保留的工作流分支，输出指令，不直接实现或归档。

openspec new change 创建变更目录和元数据
语法
openspec new change <name> [--schema <name>] [--description <text>] [--goal <text>] [--store <id>] [--json]
  • --schema：选择工作流；省略时按项目配置及根默认值解析。
  • --description：将描述写入变更目录的 README.md。
  • --goal：将目标写入 .openspec.yaml 元数据。
  • --store：选择已登记的 Store。
  • --json：输出创建结果，不自动生成完整规划。
终端示例
openspec new change add-dark-mode --store team-context --goal '支持深色主题' --json
openspec templates 查看产物模板的解析路径
语法
openspec templates [--schema <name>] [--json]

--schema 默认 spec-driven。--json 输出产物 ID 到 { path, source } 的映射，不创建产物。

openspec schemas 列出可用工作流及描述
语法
openspec schemas [--store <id>] [--json]

Schema 命令

openspec schema init 创建新的项目本地 Schema
示例
# 交互式创建 Schema
openspec schema init research-first

# 非交互式
openspec schema init rapid \
  --description "快速迭代工作流" \
  --artifacts "proposal,tasks" \
  --default
openspec schema fork 复制现有 Schema 到项目以进行自定义
示例
# Fork 内置的 spec-driven schema
openspec schema fork spec-driven my-workflow
openspec schema validate 检查 Schema 结构和模板
语法
openspec schema validate [name] [--json] [--verbose]

--json 输出验证结果，--verbose 显示详细步骤；检查工作流定义，不验证项目代码。

openspec schema which 查看 Schema 的实际解析来源
语法
openspec schema which [name] [--all] [--json]

--all 列出全部 Schema 及来源；--json 输出结构化解析结果。

🔢
Schema 优先级
1. 项目级：openspec/schemas/<name>/
2. 用户级：~/.local/share/openspec/schemas/<name>/
3. 包级：内置 Schema

配置命令

openspec config 查看和修改全局 OpenSpec 配置
示例
# 列出所有设置
openspec config list

# 获取特定值
openspec config get telemetry.enabled

# 设置值
openspec config set telemetry.enabled false

# 配置工作流 profile
openspec config profile

# 快速切换到 core profile
openspec config profile core

# 在编辑器中编辑
openspec config edit

环境变量

变量描述
OPENSPEC_CONCURRENCY批量验证的默认并发数（默认: 6）
EDITOR 或 VISUALopenspec config edit 使用的编辑器
NO_COLOR设置时禁用彩色输出，也可使用全局 --no-color
OPENSPEC_NO_ANIMATION只要设置（即使空值）就禁用 init 欢迎动画；单次可用 --no-animation
OPENSPEC_NO_COMPLETIONS=1禁用首次 Shell 补全提示，不卸载已有补全
OPENSPEC_NO_UPDATE_CHECK只要设置就禁用版本网络检查，不阻止主动安装
OPENSPEC_TELEMETRY=0禁用匿名命令名和版本统计，也禁用版本检查；可用 openspec config set telemetry.enabled false 持久关闭
DO_NOT_TRACK=1禁用追踪和版本检查
CI=true自动关闭遥测、版本检查和首次补全提示
OPENSPEC_INSTALL_DIR、OPENSPEC_VERSION独立安装目录和版本覆盖，示例见安装指南
