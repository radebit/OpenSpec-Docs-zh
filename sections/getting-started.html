安装

安装指南

独立二进制无需 Node.js；使用 npm、pnpm、yarn 或 bun 安装需 Node.js 20.19.0 或更高版本

macOS / Linux · bash
curl -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.sh | sh
Windows · PowerShell
irm https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.ps1 | iex

SHA256 校验：脚本选择最新且资产齐全的发布版，按平台下载，并对照该发布的 SHA256SUMS 验证。

  • macOS / Linux：默认安装到 ~/.local/bin，确认该目录已在 PATH。
  • Windows：默认安装到 %LOCALAPPDATA%\Programs\openspec，脚本加入用户 PATH；打开新终端生效。
  • OPENSPEC_INSTALL_DIR：覆盖安装目录。
  • OPENSPEC_VERSION=v1.15.0：锁定发布版本；PowerShell 使用 $env:OPENSPEC_VERSION = 'v1.15.0'。
macOS / Linux · 锁定版本和目录
curl -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/scripts/binary/install.sh | OPENSPEC_VERSION=v1.15.0 OPENSPEC_INSTALL_DIR="$HOME/.local/bin" sh
平台二进制
macOS 13+（Apple Silicon / Intel）openspec-darwin-arm64 / openspec-darwin-x64
Linux（glibc 2.17+）openspec-linux-x64 / openspec-linux-arm64
Alpine 3.17+openspec-linux-x64-musl / openspec-linux-arm64-musl；先安装 libstdc++、libgcc
Windows 10+openspec-windows-x64.exe / openspec-windows-arm64.exe

手动安装：从发布页下载对应文件和 SHA256SUMS，校验后重命名为 openspec（Windows 为 openspec.exe）并放入 PATH。macOS/Linux 执行 chmod +x openspec。macOS 浏览器下载的文件可能还需 xattr -d com.apple.quarantine openspec。

命令可直接复制；安装需要联网并写入本机目录，请先审查脚本。此页面不会自动执行安装。

bash
npm install -g @fission-ai/openspec@latest
bash
pnpm add -g @fission-ai/openspec@latest
bash
yarn global add @fission-ai/openspec@latest

仅 Yarn 1.x 支持 global；Yarn 2+ 请改用 npm、pnpm 或 bun。

bash
bun add -g @fission-ai/openspec@latest
ℹ️
Bun 可以全局安装 OpenSpec。此包管理器安装方式仍使用 Node.js，PATH 上需有 Node.js 20.19.0 或更高版本；独立二进制不需要 Node.js。
bash — 直接运行（无需安装）
nix run github:Fission-AI/OpenSpec -- init
bash — 安装到 profile
nix profile install github:Fission-AI/OpenSpec
💡
验证安装
openspec --version 查看版本；openspec version 确认安装来源，openspec version --check 检查升级。

升级 CLI，再刷新项目

  1. 升级 CLI：独立安装重新运行上方安装脚本；包管理器安装使用原方式升级。
  2. 审查计划：在每个项目内运行 openspec update --dry-run，检查待改文件和失败项。
  3. 刷新文件：确认后运行 openspec update。
终端 · npm 安装方式
npm install -g @fission-ai/openspec@latest
openspec update --dry-run
# 审查计划后再执行
openspec update

生成文件：update 会重写工具技能和命令文件，不能承诺保留手改。先备份。JSON 计划使用 openspec update --dry-run --json，--json 不能单独使用。

切换独立安装：openspec install（或 openspec install v1.15.0）不会自动卸载旧副本。按输出提示手动处理旧安装；旧副本可能仍优先命中 PATH。用 which -a openspec（Windows：where.exe openspec）检查，新终端运行 openspec version 应显示 standalone。

快速开始

开始你的第一个变更

初始化项目，与 AI 协作完成一个完整的功能开发流程

工具调用：下面的 /opsx: 示例使用 Claude Code 拼写。Codex 使用 $openspec-propose，Kimi Code 使用 /skill:openspec-propose 等技能形式；按工具调用对照替换，不要照搬标点。

1

初始化项目

进入你的项目目录，运行初始化命令。这将创建 OpenSpec 目录结构并为你的 AI 工具生成配置文件。

bash
cd your-project
openspec init --language '简体中文'

--language 设置新规划产物的语言。选择实际使用的 AI 工具，重启或重载后确认技能可用。Copilot 云端 coding agent 文件需 opt-in，详见初始化选项。

2

创建你的第一个变更

在 AI 对话中调用 propose 技能，描述目标，让 AI 生成提案、规范、设计和任务清单。生成后先审查这些规划产物。

AI 对话
/opsx:propose add-dark-mode
3

实现任务

用户审查并确认规划后，再调用 apply 技能按任务清单实现。发现规划需调整时先调用 update 技能，不要直接扩大实现范围。

AI 对话
/opsx:apply
4

验证后归档

先审查实现、运行项目测试，并验证规范。任务打勾和规划齐全都不等于验证通过。

终端 · 规范验证
openspec validate add-dark-mode

确认结果后调用 archive 技能。默认先校验并合并 Delta，成功后才移动变更目录；校验或合并失败不归档，CLI 以非零退出。

sync 可提前：需要先更新主规范时调用 sync 技能，但不是每次归档的必需步骤。同步失败先修复，不继续归档。

AI 对话
/opsx:archive
🔥
选择工作流
Core 默认提供 propose、explore、apply、update、sync、archive 六个技能。此处 update 是 AI 技能，不是终端的 openspec update。
如需 new、ff、verify 等扩展技能，运行 openspec config profile 选择工作流，再依次执行 openspec update --dry-run 和 openspec update。调用方式见工具调用对照。

初始化与首个变更后的目录结构

init 创建规划目录，propose 才生成首个变更的规划文件；归档后该变更位于 changes/archive/。

目录结构
openspec/
├── specs/              # 主规范（当前系统行为的权威基准）
│   └── <domain>/
│       └── spec.md
├── changes/            # 提议中的变更（每个变更独立文件夹）
│   └── <change-name>/
│       ├── proposal.md    # 为什么做、做什么
│       ├── design.md      # 如何实现
│       ├── tasks.md       # 实现任务清单
│       └── specs/         # Delta 规范（正在变化的部分）
│           └── <domain>/
│               └── spec.md
└── config.yaml         # 项目配置（可选）
